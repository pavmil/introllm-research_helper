# ADR-0001: Основной домен — ML/NLP, биомед — для проверки переноса

- **Статус:** accepted
- **Дата:** 2026-10-20
- **Связано:** design-doc §8.2, §12; [plans/week-01.md](../plans/week-01.md)

## Контекст

Черновик v0 был только про медицину. После перехода к научной литературе в целом нужен «домашний» домен. От него зависят:
- golden set (FreshSci);
- профиль рубрики доказательности;
- доступность полных текстов;
- возможность автора самому оценивать качество ответов.

## Решение

- **Основной домен — ML/NLP.** На нём строятся FreshSci, ручная разметка, профиль рубрики `ml` и основные выводы.
- **Биомед — только для проверки переноса:** SciFact, PubMedQA, LitQA2.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему нет |
|---|---|---|---|
| Биомед как основной | Сильные бенчмарки (SciFact, PubMedQA), понятная иерархия доказательств (GRADE) | Полные тексты часто за paywall; автор не эксперт — не может сам оценивать ответы; высокая цена ошибок | Без экспертизы нельзя честно собрать golden set и разметку |
| Без домашнего домена | Общность | Размытые golden set и рубрика; нечего валидировать вручную | Нет основы для H5 и FreshSci |

## Последствия

- **Плюсы:**
  - полные тексты на arXiv (в том числе LaTeX-исходники);
  - бенчмарки в домене: LitSearch, QASPER, Scholar-CS, CiteME;
  - автор может судить о качестве.
- **Минусы:** рубрика доказательности для ML менее устоявшаяся, чем GRADE. Её валидность нужно доказать (H5).
- **Что дальше:** профиль рубрики `ml` (seeds/CI, число датасетов, настроенные baseline, ablations, код).

## Когда пересмотреть

- Gate 0 показал, что в ML/NLP-вопросах у baseline нет запаса для улучшения.
- Или проект переориентируется на конкретного пользователя из другой области.
