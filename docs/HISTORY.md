## Этап 0. Идея и первый черновик (до 2026-10-20)

### Черновик «Agentic Medical Evidence Intelligence»

**Что сделано.** В обсуждении с другой LLM сформулирован исследовательский проект на 8–12 недель: мультиагентная система, которая отвечает на вопросы о медицинских исследованиях, проверяет утверждения и умеет воздерживаться от ответа.

**Решения черновика:**
- гипотезы H1–H4: verify-шаги снижают долю неподтверждённых утверждений; проверка по claims лучше проверки целого ответа; abstention; агентность нужна не всегда;
- данные: SciFact + PubMedQA (+ BioASQ);
- лестница baseline B0–B3 и ablations A1–A6;
- контроллер — конечный автомат, не больше 2 циклов коррекции;
- стек под GPU 24 GB.

**Почему.** Проект должен давать измеримый результат и материал для интервью по NLP/LLM R&D, agent systems и research engineering.

## Этап 1. Ревью и архитектура (2026-10-20)

### Ревью черновика по фреймворку ML System Design

**Что сделано.** Черновик прошёл ревью скиллом `ml-system-design-review` (фреймворк Kravchenko и Babushkin), в режиме doc-only.

**Результат:** approve with concerns (средняя оценка 2.33), одно критичное замечание.
- **Critical:** не определено, кто измеряет главную метрику («доля неподтверждённых утверждений»). Есть риск циркулярности с внутренним verifier.
- **Major:**
  - нет сравнения с готовыми системами (STORM, OpenScholar, PaperQA2, Ai2 ScholarQA);
  - нет baseline при равном бюджете вычислений;
  - утечки: в PubMedQA вопрос совпадает с заголовком статьи; старые бенчмарки, скорее всего, есть в претрейне LLM;
  - корпус не привязан к бенчмаркам;
  - нет таблицы цены ошибок;
  - нет механизма оценки силы доказательств.

**Ссылки:** [reviews/2026-10-20-mlsd-scorecard-draft-v0.md](reviews/2026-10-20-mlsd-scorecard-draft-v0.md), [design-doc.md](design-doc.md) §1.

### Основа — STORM / Co-STORM, домен — научная литература в целом

**Решения:**
- Взять за основу STORM (перспективы + симулированные диалоги + outline) и Co-STORM (модератор → Gap Critic, mind map → карта доказательств).
- Расширить домен с медицины до научной литературы в целом.

**Почему.**
- STORM даёт ширину: находит «неизвестные неизвестные». Черновик v0 был узким: вопрос разбивался на claims одной перспективы.
- Известные слабости STORM — перенос предвзятости источников и связывание несвязанных фактов — закрываются проверкой на уровне утверждений.

**Ссылки:** design-doc §4, §5.

### Ключевые архитектурные решения (design doc v0.1)

**Решения:**
1. **Evidence ledger** — единственный источник истины. Агенты обмениваются записями (статьи, фрагменты, утверждения, проверки, пропозиции), а не прозой.
2. **Verify-before-write.** Непроверенное утверждение не попадает в ledger.
3. **Ссылки по построению.** Writer ставит ID, рендерер превращает их в ссылки, поэтому выдуманная ссылка невозможна (ADR-0003).
4. **LLM предлагает, код решает.** Детерминированный FSM-контроллер, бюджеты, не больше 2 раундов gap-поиска (ADR-0002).
5. **Сила доказательств.** LLM извлекает проверяемые признаки с привязкой к фрагментам, уровень считает прозрачная рубрика. Её валидность проверяется гипотезой H5.
6. **Оценка:**
   - независимый судья другого семейства моделей с калибровкой на ручной разметке;
   - baseline при равном бюджете, включая ванильный STORM (B3) и PaperQA2 (B5);
   - свежий golden set FreshSci против контаминации.

**Ссылки:** [design-doc.md](design-doc.md).

### Домашний домен — ML/NLP

**Решение:** основной домен — ML/NLP, биомед — только для проверки переноса.

**Почему.**
- Полные тексты на arXiv.
- Бенчмарки в домене: LitSearch, QASPER, Scholar-CS, CiteME.
- Автор может сам оценивать качество ответов.

**Ссылки:** [ADR-0001](adr/0001-home-domain-ml-nlp.md).

### План недели 1 с Gate 0

**Решения:**
- Перед написанием своей системы прогнать B0, ванильный STORM и PaperQA2 на 5 вопросах и разметить 150 утверждений.
- Gate 0: есть ли запас для улучшения по достоверности и полноте.
- Golden set пишется **до** любых прогонов.

**Почему.** Не строить систему, пока не доказано, что базовые решения ошибаются там, где мы собираемся улучшать.

**Ссылки:** [plans/week-01.md](plans/week-01.md), [labeling-guide.md](labeling-guide.md).

## Этап 2. Инфраструктура репозитория (2026-10-20)

### Bootstrap репозитория `introllm-research_helper`

**Что сделано:**
- Структура каталогов.
- Документы для людей и агентов: README, AGENTS.md, CLAUDE.md, CONTRIBUTING.md, контекст, глоссарий, ADR, шаблон задач.
- Код: `uv` + ruff + mypy strict + pytest (таймауты, покрытие ≥ 80%) + pre-commit; GitHub Actions; `LoopGuard`; базовые схемы ledger; хук Claude Code против зацикливания.

**Решения:**
- **AGENTS.md** — единый источник правил для любых агентов. CLAUDE.md только импортирует его и добавляет специфику Claude Code.
- **Работа агентов — только по файлу задачи** (`docs/tasks/`, шаблон с контекстом, scope, контрактами, критериями приёмки и стоп-условиями). Агент лучше выполняет заранее расписанную задачу.
- **Защита от зацикливания на трёх уровнях:**
  - `LoopGuard` в коде продукта;
  - хук `.claude/hooks/loop_guard.py` для dev-агента;
  - таймауты в pytest и CI.
- **`make check`** — одна команда и локально, и в CI.
- **CD отложен** до этапа демо (неделя 12): деплоить пока нечего.

**Почему.** Основная разработка будет идти силами ИИ-агентов. Правила, контекст и автоматические проверки должны быть до первого кода.

**Ссылки:** [T-0001](tasks/0001-bootstrap-repository.md), [ADR-0002](adr/0002-deterministic-controller-and-loop-guard.md).
