# Гайд разметки: подтверждает ли источник утверждение

*Черновик v0 · используется на неделе 1 и для калибровки судьи (design doc §8.5)*

## Единица разметки

Пара **(утверждение из ответа системы, процитированные им источники)**.

**Утверждение** — одна атомарная мысль, которую можно проверить. Если в предложении их несколько («X улучшает F1 на 3 п.п. и снижает latency»), раздели его на два утверждения.

Утверждения без ссылок тоже размечаются: метка `NO_CITATION`.

## Метки

| Метка | Когда ставить |
|---|---|
| `SUPPORTED` | В процитированном источнике есть фрагмент, прямо говорящий то же самое (пересказ допустим). Условия совпадают: датасет, модель, настройка |
| `PARTIAL` | Подтверждена только часть утверждения, **или** утверждение шире источника: потеряны условия, обобщено на другие модели или данные. Обязательно добавь тег |
| `NOT_SUPPORTED` | Источник существует и доступен, но этого не говорит. Если говорит противоположное — тег `contradicted` |
| `CITATION_INVALID` | Источника не существует, ссылка ведёт на другую работу или её невозможно разрешить |
| `NO_CITATION` | Содержательное утверждение без ссылки |
| `UNVERIFIABLE` | Источник недоступен (paywall, битый PDF). **Исключается из долей**, считается отдельно |

## Теги ошибок (можно несколько)

- `overgeneralized` — вывод шире условий исследования
- `wrong_number` — число не совпадает с источником
- `contradicted` — источник говорит обратное
- `source_bias` — оценочный язык аннотации («significantly outperforms») подан как установленный факт
- `wrong_section` — утверждение опирается на Related Work или Intro источника, а не на его собственные результаты
- `merged_conditions` — склеены результаты из разных условий или статей

## Процедура

1. Открой ответ системы и случайно выбери 10 утверждений, равномерно по разделам. Можно скриптом: пронумеровать предложения → выбрать → разбить на атомарные.
2. Для каждого утверждения открой процитированный источник и найди лучший подтверждающий фрагмент. Ищи и в полном тексте, и в таблицах.
3. Поставь метку и теги, **скопируй найденную цитату** в `evidence_quote` (пусто, если не нашёл).
4. Засеки время — нужно для оценки стоимости разметки.
5. Сомневаешься между двумя метками — ставь более строгую и пиши причину в `note`.

## Формат `labels.csv`

```
system,question_id,claim_id,claim_text,cited_ids,label,tags,evidence_quote,minutes,annotator,round,note
storm,fs-dev-003,storm-003-07,"...","arXiv:XXXX.XXXXX",PARTIAL,overgeneralized,"...",2.5,me,1,"в статье только math"
```

- `round` — 1 для основной разметки, 2 для повторной (20 пар через 3–4 дня, не глядя на первую).
- Согласованность считается по парам, у которых есть оба раунда (Cohen's κ по метке).

## Уровень ответа (отдельная таблица, по golden set)

`coverage.csv`: `system, question_id, kp_id, covered (yes/partial/no), conflict_found (yes/no/na), key_papers_cited (n из N)`.
