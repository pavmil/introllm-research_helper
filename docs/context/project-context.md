# Контекст проекта на одной странице

*Для людей и агентов: прочитать первым. Детали — в [design-doc](../design-doc.md).*

## Что строим

Систему, которая по исследовательскому вопросу («Работает ли X для Y?», «Какие методы решают Z?») возвращает **структурированный обзор литературы**:
- краткий ответ с уровнем доказательности;
- карту доказательств «за» и «против»;
- таблицу методов и результатов;
- противоречия;
- явные ограничения: доказательной базы, поиска и самой системы.

Каждое утверждение обзора ведёт к конкретному фрагменту конкретной статьи.

## Для кого и зачем

- **Пользователь** — исследователь или ML-инженер, которому за час-два нужно понять, что известно по вопросу.
- **Чем плохо сейчас:**
  - ручной поиск медленный и пропускает противоречащие работы;
  - LLM-ассистенты часто ссылаются на источники, которые не подтверждают утверждение.
- **Мета-цель:** исследовательский портфолио-проект с честно измеренным результатом, включая отрицательный.

## Как устроено

STORM-подобное многоперспективное исследование + **evidence ledger**:

```
Scope → Discovery + Reader → Перспективы и диалоги (Asker ↔ Expert)
      → Verifier → Ledger → Consolidator + Gap Critic → Controller (≤2 раунда)
      → Writer (только из ledger, ссылки по ID) → Auditor → Отчёт
```

**Принципы:**
1. LLM предлагает, код решает.
2. В ledger только проверенное.
3. Ссылки собирает код.
4. Бюджеты и `LoopGuard` на каждом цикле.
5. Live- и Frozen-режимы различаются только источником данных.

## Чего не делаем (antigoals)

- Клинические, юридические и иные профессиональные рекомендации.
- Замена систематического обзора.
- Генерация гипотез и статей.
- Обход paywall.
- Продакшен-SaaS.
- Обучение своей LLM — дообучаем только небольшой verifier.

## Как поймём, что получилось

| Цель | Метрика |
|---|---|
| Достоверность | Claim support rate (доля утверждений, подтверждённых процитированным фрагментом) по оценке **независимого** судьи |
| Полнота | Recall ключевых пунктов из экспертных рубрик (Scholar-CS, FreshSci) |
| Отказ от ответа | Selective accuracy и AURC (LitQA2, PubMedQA) |
| Цена | Токены, $, время на отчёт |

Все сравнения — при равном бюджете вычислений. Ключевой baseline — ванильный STORM.

## Ограничения

- Один разработчик + ИИ-агенты.
- GPU 24 GB: локальная LLM 7–8B, остальное — API.
- 12 недель (сокращаемо до 8).
- Домен: ML/NLP — основной, биомед — для проверки переноса.
