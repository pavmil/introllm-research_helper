# Глоссарий

Термины используются в коде (`src/research_helper/schemas/`) и в документах в одном значении.

## Данные и ledger

| Термин | Значение |
|---|---|
| **Paper** | Статья с метаданными: S2 ID, DOI или arXiv ID, год, venue, флаги `peer_reviewed`, `is_retracted`, уровень текста (full / abstract) |
| **Span** | Фрагмент статьи: одно или несколько подряд идущих предложений в разделе. Адресуется как `paper_id:section_idx:start-end`. Единица цитирования |
| **Paper Card** | Структурированная выжимка статьи: тип исследования, методы, датасеты, метрики, результаты с условиями, ограничения. У каждого поля есть подтверждающие span. Не зависит от вопроса и кешируется |
| **Claim** | Атомарное проверяемое утверждение из одной статьи с привязкой к span |
| **Verification** | Вердикт verifier для пары (claim, span): SUPPORTS / REFUTES / NEI + вероятность |
| **Proposition** | Обобщённое утверждение, объединяющее claims из разных статей. Хранит поддерживающие и опровергающие claims, признаки и уровень доказательности |
| **Conflict** | Пара противоречащих claims внутри пропозиции. Тип: прямое противоречие, разные условия, метрики или популяции |
| **Evidence level** | Уровень доказательности пропозиции: strong / moderate / limited / conflicting / insufficient. Считается рубрикой по признакам, а не напрямую LLM |
| **Evidence ledger** | Хранилище всех записей выше в рамках прогона. Единственный источник для написания обзора |

## Агенты и компоненты

| Термин | Значение |
|---|---|
| **Scope Agent** | Разбирает вопрос: тип, подвопросы, ограничения, доменный профиль |
| **Discovery Agent** | Ищет статьи в нескольких источниках, расширяет поиск по цитированиям |
| **Perspective** | Точка зрения, с которой исследуется тема: методолог, скептик, практик… Аналог персон STORM |
| **Asker / Grounded Expert** | Пара в исследовательском диалоге: Asker задаёт вопросы с позиции перспективы, Expert отвечает claims со ссылками на span |
| **Verifier** | Модель, которая проверяет пару (claim, span). Внутренний компонент — **не** используется как судья при оценке |
| **Consolidator** | Объединяет claims в пропозиции, ищет конфликты, считает признаки доказательности |
| **Gap Critic** | Находит непокрытые подвопросы и найденную, но не использованную информацию. Аналог модератора Co-STORM |
| **Controller** | Детерминированный конечный автомат: решает, искать ли дальше, писать или воздержаться |
| **LoopGuard** | Защита каждого цикла: бюджеты шагов, вызовов, токенов, $, времени, детекция повторов и отсутствия прогресса |
| **Writer** | Пишет обзор только из пропозиций ledger, ссылки — ID |
| **Attribution Auditor** | Проверяет каждое предложение обзора по процитированным span и сверяет числа |

## Оценка

| Термин | Значение |
|---|---|
| **Claim support rate** | Доля атомарных утверждений обзора, подтверждённых процитированными span, по оценке независимого судьи |
| **Независимый судья** | Модель другого семейства, чем Writer и Verifier, откалиброванная на ручной разметке |
| **Coverage / AURC** | Доля вопросов, на которые система ответила / площадь под кривой risk–coverage |
| **Abstention** | Отказ от вывода при недостатке доказательств. На трёх уровнях: claim, предложение, ответ |
| **FreshSci** | Свой golden set: вопросы о работах после knowledge cutoff LLM. Ключевые пункты пишутся до прогонов систем |
| **B0–B5** | Baseline: B0 без retrieval, B1 RAG, B2 RAG + verifier, B3 ванильный STORM, B4 наша система, B5 PaperQA2 |
| **Равный бюджет (compute-matched)** | Сравнение систем при одинаковом числе токенов и вызовов |
| **Gate** | Контрольная точка плана с явным критерием «идём дальше / меняем фокус» |
| **Live / Frozen** | Режимы работы: реальные API / замороженный корпус + повтор записанных запросов (record/replay) |
